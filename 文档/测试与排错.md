# 壳语言 测试与排错

> 用法见 [使用手册](使用手册.md)，结构见 [实现说明](实现说明.md)。

## 1. 构建与自检

```sh
cargo build                # 调试版，产物 target/debug/shell-lite
cargo build --release      # 发布版，LTO + strip
cargo test                 # 单元测试
cargo clippy               # 静态检查（当前 0 警告）
```

单元测试位于 [`src/模块/词法.rs`](../src/模块/词法.rs) 底部的 `mod 测试`，覆盖：

| 测试 | 覆盖内容 |
| --- | --- |
| `基本分词与引号` | 中文参数、单引号不展开变量、双引号内变量展开且不切分 |
| `管道与重定向` | 多段管道、`>`、`2>&1` 的作业级记录 |
| `错误重定向` | `2>>`、`<`、`&>` 被后续 `2>` 覆盖、`2-3` 不被误识别 |
| `后台与分号` | `&` 与 `;` 的作业拆分 |
| `变量与波浪号` | `$名字`、`${HOME}`、`~/x`、未定义变量为空串 |
| `前置赋值` | `A=1 B="x y" echo hi` 的拆分 |
| `引号未闭合` / `空管道报错` | 典型语法错误的分类 |
| `通配匹配` | `*`、`?`、`[a-c]`、`[!a-c]`、中文 |
| `注释与续行` | `#` 注释、`\`+换行 |
| `管道与后台不冲突` | `sleep 1 & echo \|& cat`、`&>` 与后台符区分 |
| `管道与错误` | `\|&` 与 `2>&1 \|` 的差异 |
| `单引号段按字面量处理` | `'A'"$HOME"` 只有单引号段是字面量、`'a\'b'`、双引号转义、`~` 只在无引号时展开 |
| `井号紧跟引号内容` | 引号里的 `#` 与紧跟在引号后面的 `#` |
| `中文变量赋值` | 中文变量名（曾经因按字节切片而崩溃） |

一条命令跑一遍全部行为（手工验收脚本）：

```sh
shell-lite -c 'printf "甲\n乙\n甲\n" | sort | uniq -c'
shell-lite -c 'ls /不存在的路径 2>&1 | wc -l'        # 1
shell-lite -c 'yes | head -1'                        # 应立刻返回，不卡住
shell-lite -c 'exit 7'; echo $?                      # 7
```

## 2. 开发中踩过的坑（排错时先看这里）

### 2.1 管道读端永远等不到 EOF

**现象**：`seq 1 100 | wc -l` 卡住。
**原因**：父进程分叉完没有关闭管道写端——即使所有子进程都退出了，写端还开着，读端就等不到 EOF。
**做法**：子进程里 `重定向描述符` 接好之后立刻关闭两端；父进程在分叉循环结束后关闭全部管道端。

### 2.2 `dup2: Bad file descriptor`

**现象**：`cat < 文件`、`printf ... | cat | wc -l` 报 `重定向描述符` 失败。
**原因**：在完成 dup 之前就把「本进程要用」的管道端关掉了。
**做法**：先只关闭本进程**用不到**的端，要用的端记在变量里，dup 完再关。

### 2.3 `yes | head -1` 卡住

**现象**：`head` 已经打印完毕并退出，shell 还在等 `yes`。
**原因**：shell 自己继承了「忽略 SIGPIPE」，`yes` 写管道时收不到 SIGPIPE，一直写。
**做法**：子进程 `恢复信号默认()`；并且任意一段被信号终止时走 `收尾`，不再等上游。

### 2.4 后台作业在 `-c` 模式结束后被挂起

**现象**：`shell-lite -c 'sleep 1 &'` 之后，那个 `sleep` 进程停住（`ps` 里状态为 `T`）—— 未启用作业控制时的典型表现。
**原因**：子进程的标准输入仍连着终端但不在前台进程组，读终端会收到 SIGTTIN。
**做法**：后台作业 `设置进程组(0, 0)` 自成一组。

### 2.5 退出 shell 时命令被 Ctrl-C 打断

**现象**：`Command` 建立的子进程偶尔直接退出。
**原因**：Rust 的 `Command` 会在分叉到换程序之间短暂屏蔽信号，若 shell 此时把 SIGINT 恢复成默认，就会命中。
**做法**：shell 先 `设置信号处理(SIGINT, 忽略信号)` 再分叉，子进程换程序前再恢复默认。

### 2.6 中文变量名导致崩溃

**现象**：`名字=值` 引发 `not a char boundary` panic。
**原因**：赋值识别时用「字符数」当「字节偏移」去切字符串，中文占多字节会切在字符中间。
**做法**：统一按 `chars()` 切分（`收集词` 里的「去掉名称与等号」那一段）；已补测试 `中文变量赋值`。

### 2.7 单引号里面写单引号

**现象**：`echo 'a\'b'` 报「引号 ' 未闭合」。
**原因**：实现早期单引号内不认任何转义。
**修复**：单引号内按 bash 的规则只认 `\'`；引号保护改为**按字符记录**（`词` 里的字面量区），所以 `'a'$HOME` 能正确展开 `$HOME`。

### 2.8 引号语义混淆

**现象**：`sh -c 'echo $名字'` 输出 `$名字`；`'A'$HOME` 不展开。
**原因**：不是 bug，是规则——单引号内的 `$` 不展开（按字符保护，单引号外面的部分照常展开）。
**用法**：需要子 shell 看到变量时写 `sh -c "echo $名字"`（双引号，且先 `export`）。

## 3. 报错对照

| 输出 | 含义 | 排查方向 |
| --- | --- | --- |
| `语法错误：引号 X 未闭合` | 引号没配对 | 检查引号 |
| `语法错误：缺少命令` | `\|`/`&`/`;` 后为空，或用了 `&&`/`\|\|` | 补齐命令或换写法 |
| `语法错误：重定向缺少目标文件` | 重定向符号后没有文件名 | 补文件名 |
| `语法错误：意外的符号 `(`` | 不支持子 shell | 改 `sh -c '...'` |
| `语法错误：行尾反斜杠没有可转义的字符` | 行末孤立 `\` | 删除或补字符 |
| `shell-lite: 程序: 未找到命令` | execvp 返回 ENOENT | 检查 `PATH`、拼写 |
| `shell-lite: 程序: 权限不足` | EACCES | `chmod +x` |
| `shell-lite: 路径: No such file or directory` | 重定向目标打不开 | 检查目录 |
| `创建子进程失败 / 创建管道失败` | 系统资源不足 | 检查进程数上限 |

## 4. 已知限制（不是 bug）

- 只面向 Linux（`O_*` 常量按 Linux 取值，glibc 下验证）；
- 没有 `&&`/`||`/`if`/循环/函数/命令替换/子 shell，也没有 `jobs`/`fg`/`bg`；
- 后台作业结束不打印通知（没有 SIGCHLD 处理），由系统回收；
- 交互模式没有行编辑：方向键、Tab 补全、历史都不可用；`Ctrl-C` 会终止正在运行的前台命令（子进程恢复默认处理），不会清掉已经打了一半的输入行；
- `$变量` 展开出来的内容不再参与通配；
- 反斜杠可以转义任意字符（包括 `<`、`|`），与 bash 只在少数语境允许转义不同；
- 启动文件只读 `~/.壳语言rc`，没有系统级配置。
