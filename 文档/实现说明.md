# 壳语言 实现说明

> 面向想读源码或改代码的人。用法见 [使用手册](使用手册.md)。

## 1. 总体结构

```text
脚本文本 ─►┌──────────────────┐  语句树  ┌──────────────┐  作业  ┌──────────────┐  管道片段  ┌──────────────┐
          │ 词法::解析脚本     ├────────►│ 词法::解析命令├──────►│   释义.rs    ├─────────►│   执行.rs    ├─► fork/exec
          └──────────────────┘          └──────────────┘        └──────────────┘            └──────────────┘
             │ 按行首关键字切块，           │ 分词、引号、管道、       │ 变量/~ /通配展开、      │ 建管道、接描述符、
             │ 块体递归成语句树             │ 重定向、后台、赋值       │ 拆前置赋值、标出内置    │ 等待、收尾
                     ▼                             ▼                        ▼                         ▼
                  语句树                          作业                   管道片段               子进程 + 退出状态
                                                          ▲
                                      壳.rs 递归执行语句树、维护变量与 $?、提示符
                                                          │
                                      内置.rs：打印目录 / 环境变量 / 输出文本 ……（shell 自身命令）
                                      系统.rs：C 库声明 + 中文安全封装
```

控制流在词法层新增独立的**语句层解析**（`解析脚本`）：按逻辑行与行首裸词切块，每行内容仍交给
已充分测试的 `解析命令()`，因此管道、重定向、后台、引号、注释等语法全部原样复用。
`语句` 枚举递归包含块体；`壳.rs` 用 `执行语句列表()` / `执行语句()` 递归执行，
`跳出`/`继续` 用返回值里的 `流` 信号向上传播，由最近的循环消费。

## 2. 词法层：`词法.rs`

### 2.1 数据结构

```rust
pub struct 词 {
    pub 文本: String,     // 引号只决定展开方式，引号本身不进文本
    pub 含单引号: bool,   // 整词原样，不做任何展开
    pub 含双引号: bool,   // 变量展开，但不通配、不展开 ~
}

pub struct 简单命令 {
    pub 赋值: Vec<(String, 词)>,  // 前置赋值 A=1
    pub 词列表: Vec<词>,
}

pub enum 连接方式 { 管道, 管道含错误 }   // | 与 |&

pub struct 管道 { 命令: Vec<简单命令>, 连接: Vec<连接方式> }

pub struct 作业 {
    管道: 管道,
    输出: Option<(词, bool)>,      // (目标, 是否追加)
    错误输出: Option<(词, bool)>,
    输入: Option<词>,
    合并错误: bool,                // 写过 2>&1
    后台: bool,
}
```

一条作业 = 一段管道 + 整段共享的重定向信息。`2>&1 |` 里的 `2>&1` 属于**作业级**，不是段级，所以 `合并错误` 放在 `作业` 上；`|&` 才是段级的，放在 `连接方式` 里。

### 2.2 解析器

`解析器` 是单遍扫描的字符游标（`字符表` + `当前位置`），状态是「正在拼的词」「当前命令」「当前管道」「当前作业」。

- 词的处理：空白或操作符处 `收集词()`；
- **后台关键字**：词被收集时，若它正好是裸写的 `异步运行`、位于命令名位置且未被引号保护，就把 `当前作业.后台` 置位、该词本身不进入命令词列表；其后没有命令时报「缺少命令」。下游（释义/执行）只看 `后台` 标志，无需知道是哪个语法写出来的；旧写法 `命令 &` 走主循环里的分支，同样置位；
- **赋值前缀识别**：记录当前词里第一个**未加引号**的 `=` 的位置（`赋值等号位置`，按字符计）。词被收集时，如果命令名还没出现、且 `=` 之前是合法的名称，就拆成 `赋值`；
- `2>` 只在「词的开头位置且紧跟 `>`」时才当作描述符前缀，所以 `echo 2-3` 仍然是一个参数；
- `|&` 的 `&` 由主循环里的规则识别：如果「已经收好的命令数」比「连接数」少 1，说明这是紧跟在 `|` 后面的 `&`，跳过而不是当作后台符；
- 行尾的 `\`+换行被直接吞掉，实现续行。反斜杠转义只对**下一个字符**生效，`\<`、`\ ` 等任意字符都会被原样保留（与 bash 略有不同：bash 只在少数语境里允许 `\<`）。

结束时若「命令数 ≤ 连接数」（例如 `echo a |`），报 `缺少命令`。

### 2.3 展开

| 函数 | 作用 |
| --- | --- |
| `展开词(词, 查变量) -> Vec<String>` | 变量/`~` 展开，再按需通配；一个词可能变成多个文件 |
| `展开变量(词, 查变量) -> String` | 处理 `$名称`、`${名称}`；`~`、`~/x` 只在无引号且位于词首时展开 |
| `通配展开(模式) -> Option<Vec<String>>` | 扫目录、过滤、排序；无匹配返回 `None`（保留原样） |
| `模式匹配(模式, 文本) -> bool` | 支持 `*` `?` `[...]`，用「记住最近一个 `*` 并在失配时回退」的经典算法 |
| `字符类匹配(...)` | 解析 `[...]`，支持范围与 `!`/`^` 取反 |

## 3. 释义层：`释义.rs`

释义器对一条作业做释义，返回三种结果之一：

| 结果 | 条件 | 交回给谁 |
| --- | --- | --- |
| 空 | 只有空白/注释 | 什么也不做 |
| 赋值 | 只有 `A=1 B=2`，没有命令 | `壳` 修改自己与环境 |
| 管道片段 | 其余情况 | `壳` 执行 |

在转换成 `管道片段` 时：

- 每个词展开成实参（一个词可能展开成多个文件）；
- 前置赋值 `A=1 cmd` 展开后放进该命令的 `环境`（只给子进程）；
- 如果命令出现在管道或后台里、又恰好是内置命令名，就把 `内置 = true` 标出来——执行层会分叉出子进程去跑内置实现。

## 4. 执行层：`执行.rs`

### 4.1 两条路径

| 入口 | 条件 | 做法 |
| --- | --- | --- |
| `运行单个` | 单命令、无重定向、无后台（由 `壳` 判断） | 直接用标准库起子进程并等它结束 |
| `运行管道` | 其余情况 | 自己 `分叉进程` + `创建管道` + `重定向描述符` + `执行程序` |

### 4.2 运行管道 的步骤

1. **先在父进程打开全部重定向文件**：任何一个打不开，直接报错返回，不会留下半个进程；
2. 为 `n` 段命令创建 `n-1` 个管道；
3. 每段分叉一个子进程，子进程中依次：
   1. `恢复信号默认()` —— 不能继承 shell 的「忽略 SIGINT」；
   2. 后台作业 `设置进程组(0, 0)` 自成一组；
   3. **先关闭本进程用不到的管道端**（本进程要用的读端/写端先记住）；
   4. 用 `重定向描述符` 把输入文件 / 上一段管道 / 本段管道 / 输出文件 / 错误文件接到 0/1/2；
   5. 关闭已接好的描述符，返回 `Result`，失败就写一条错误并 `立即退出(1)`；
   6. `替换运行()`：内置命令直接跑内置实现后退出；否则 `系统::替换运行()`（execvp），失败时打印「未找到命令」或「权限不足」，退出码 127/126；
4. 父进程关掉所有管道端和文件；
5. 后台作业：打印 `[进程号] 已放入后台` 后直接返回 0；
6. 前台：按顺序 `等待进程`。

### 4.3 顺序上的两个坑

- **先关不用的管道端，再 dup，最后 exec**：如果在 dup 之前把本进程还没接好的 fd 关掉，`重定向描述符` 就会得到 `EBADF`。开发中确实踩到过。
- **等待时的信号处理**：`等待进程` 返回 `(状态码, 终止信号)`。任意一段被信号杀死（典型是 `yes | head -1` 中 `yes` 收到 SIGPIPE，或用户按了 `Ctrl-C`），就进入 `收尾`：先等完下游各段，再给上游残留进程发 SIGTERM 并回收，避免 shell 卡死或留下后台僵尸。
- **父进程同样要设一次进程组**：子进程的 `设置进程组` 与父进程的调用会竞争，两边都设可以避免时序问题。

### 4.4 内置命令的重定向：`重定向守护`

内置命令在 shell 自身进程里跑，没法用分叉来隔离描述符。`重定向守护::应用(重定向)` 先 `复制描述符` 备份 0/1/2，再 `重定向描述符` 指向目标；`Drop` 时先冲刷 Rust 的标准流缓冲，再恢复备份。这样 `输出文本 内容 > 文件`、`打印目录 > 文件` 与外部命令表现完全一致。

## 5. 内置层：`内置.rs`

- `内置命令` 是中文变体名（`进入目录`、`压栈目录`、`弹栈目录`、`退出进程`、`加载脚本`、`输出文本`……），`全部` 表把命令行里的名字（`进入目录`、`cd`、`输出文本`……）映射到变体；
- `压栈目录` / `弹栈目录` 用的目录栈放在 `壳::目录栈`，通过 `上下文.目录栈` 借给内置命令；
- `加载脚本` 通过 `上下文.执行脚本文件`（一个 `FnMut` 回调）回到 `壳::执行脚本文件` 逐行执行，所以脚本里的变量和目录变化都留在当前 shell；
- `运行(参数, 上下文)` 返回退出状态，`上下文` 里带变量表（可变借用）与 `退出` 标志；
- 内置命令只读写标准流，不知道自己在终端、管道还是文件里。

## 6. 调度层：`壳.rs`

```text
运行脚本文本 / 执行脚本文件 / 运行输入（交互攒行）
  └─ 词法::解析脚本 → 语句树（Err: 打印「语法错误：第 N 行：…」，状态码 2）
       └─ 执行语句列表 → 对每个语句:
            ├─ 作业列表 → 执行作业列表（原「运行一行」的循环体）
            ├─ 如果     → 逐分支执行条件作业，首个退出码 0 的执行其体，否则执行否则体
            ├─ 对于     → 展开取值逐个写入循环变量，执行体；消费「跳出」/「继续」
            ├─ 每当     → 条件退出码 0 时循环执行体；消费「跳出」/「继续」
            ├─ 函数     → 注册到函数表（定义时不执行体）
            ├─ 返回     → 返回 `流::返回`，由最近函数调用消费
            └─ 跳出/继续 → 返回 `流` 信号，由最近循环消费
                 执行作业列表 → 对每个作业:
                      ├─ 释义器{环境表快照, 最后状态}.释义(作业)
                      ├─ 空      → 忽略
                      ├─ 赋值    → 变量表 + 进程环境 都更新
                      └─ 管道    → 执行管道(片段)
                           ├─ 函数调用（单命令）: 绑定命名/位置参数 → 执行函数体 → 恢复参数
                           ├─ 内置命令（单独、非后台）: 重定向守护 → 运行 → 写回变量表 → 重设进程环境
                           └─ 否则: 运行单个 / 运行管道
```

关键点：

- **变量同时存在于 `变量` 表与进程环境**。赋值和 `环境变量`（旧名 `export`）都会 `set_var`，这样 `A=1 env` 这类外部命令就能看到；内置命令改完变量后调用 `重设进程环境()`，把 `unset` 掉的键从进程环境里也删掉；
- **内置命令的所有权**：单独出现的 `cd`、`环境变量` 直接改 shell；出现在管道/后台里的由子进程执行，不会改 shell；
- **`退出进程`**（旧名 `exit`）：内置命令置位 `上下文.退出`，`壳` 记下 `退出码` 后停止执行后续作业；`main` 用它作为进程退出码。

## 7. 系统调用层：`系统.rs`

零依赖的代价是手写 C 库声明。Rust 的两条限制决定了这里的写法：

1. `extern "C"` 块里的函数名同时就是 C 符号名，**不能用非 ASCII 标识符**；
2. `execvp`、`open`、`write` 等名字与 std 内部的运行库绑定冲突，直接写成同名会编译失败或被链接到错误目标。

因此：

```rust
mod c接口 {
    unsafe extern "C" {
        #[cfg_attr(target_os = "linux", link_name = "open")]
        pub fn r#open(路径: *const 字符, 标志: 整数, ...) -> 整数;   // 可变参数，与 glibc 原型一致
        // …
    }
}

// 外面一层：中文安全封装，其余模块只用这层
pub fn 打开文件(路径: *const 字符, 标志: 整数) -> 整数 { … }
```

常量与外层函数用中文名；`O_CREAT` 这类 ABI 数值常量保留 C 库原名。

## 8. 中文命名的边界

| 可以自由命名的 | 不能改的 |
| --- | --- |
| 目录、文件（`模块/壳.rs`） | Rust 入口 `main` |
| 类型、模块、函数、变量、闭包参数、模块标签 | `extern "C"` 块内的函数名 |
| 错误信息、注释、文档 | 语言关键字与标准库接口（`std::`、`Vec`、`Some`……） |
| | 外部命令名与命令行选项（`ls`、`-c`、`-n`） |
| | C 库 ABI 常量（`O_CREAT`、`EINVAL`……） |
| | 可执行文件名 `壳`（按既定约定） |

模块索引文件（本项目的 `模块.rs`）和入口（`主体.rs`）都由 `#[path]` 显式指定：Rust 只按「目录名 + `mod.rs`」或入口标识符自动找文件，中文名无法由标识符推出，所以在 `主体.rs` 里写 `#[path = "模块/模块.rs"] mod 模块;`，`模块.rs` 里再用 `#[path = "壳.rs"]` 为每个子模块接线。

## 9. 扩展指南

想加功能，大体按下面的顺序改：

| 想加的 | 改哪里 |
| --- | --- |
| 新的内置命令 | `内置.rs`：加变体、加进 `全部`、写 `运行` 分支 |
| 新的重定向形式 | `词法.rs` 解析器 + `作业`/`重定向` 结构 + 执行层的接线 |
| 新的展开（如 `${名称:-默认值}`） | `词法::展开变量` |
| `&&` / `||` | `词法` 增加连接类型、`作业`/`管道片段` 增加连接信息，`壳` 调度时根据上一条状态决定跳不跳过 |
| 新的控制流关键字 | `词法::解析脚本` 的行首分派 + `语句` 枚举 + `壳::执行语句` 分支 |
| 函数特性（如局部变量） | `壳::执行函数调用` 的参数保存/恢复逻辑 + `函数表` |
| 命令替换 `$(...)` | 解析阶段先做一遍「抽取 → 用本 shell 执行 → 文本回填」 |
| 作业控制（`jobs`/`fg`） | 后台作业本来已自成进程组，再补 `tcsetpgrp` 把前台终端交给它 |
| 行编辑 / 历史 | 读入循环换成终端原始模式自绘，或引入 readline 类依赖（会打破零依赖） |

改完记得：

```sh
cargo test      # 词法/展开的单元测试，新行为尽量补一条
cargo clippy    # 目前零警告
```
